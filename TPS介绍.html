请求缓存 规划中

相同或近似的请求无需每次都打到大模型，命中缓存时直接返回历史响应。既降低成本，又显著提升响应速度，尤其适合事实型问答、结构化分类等重复度高的场景。

规划范围：同时覆盖精准缓存（完全相同的请求）和语义缓存（含义相同的近似请求）两种形态，由业务场景自主选择启用粒度。

1全响应式网络层

从客户端到上游 LLM 的请求与响应全程异步非阻塞
全链路非阻塞：单实例可承载上千并发长连接，流式响应持续数十秒也不占用业务线程
过滤器即能力：鉴权、路由、Skill 注入、敏感词、计量、日志以过滤器形式串联，新增能力只需插入新过滤器，不改动核心流程
流式零拷贝：SSE 流式响应以原始字节直通客户端，降低延迟与 CPU 开销
优雅升级：Pod 滚动升级期间追踪存量请求，新请求先摘除、老请求自然完成

2多级缓存架构

本地缓存 + 分布式缓存 + 数据库三级联动
分层回源：高频配置从本地内存读取（微秒级），未命中走分布式缓存（毫秒级），再未命中才回源数据库
跨实例同步：任一实例修改配置后通过消息总线广播，其他实例主动刷新，避免多实例数据漂移
启动预热：实例启动时批量加载全部配置到本地，首个请求即命中缓存

3智能路由与负载均衡

基于场景、能力、健康状态的多维度决策
能力感知：自动识别请求所需能力，只在支持该能力的渠道间选择
多策略可选：加权轮询、最少连接等多种负载均衡策略按业务场景灵活切换
故障隔离：异常渠道自动熔断摘除，恢复后试探性放量验证
自动降级：主模型不可用时按预设链路切换到备选模型

4异步写库 + 实时配额

配额走强一致路径保证业务准确，日志走最终一致路径保证热路径零阻塞
热路径零阻塞：请求响应阶段不依赖数据库写入，数据库抖动不会影响业务响应延迟
配额毫秒级一致：配额扣减走分布式原子操作，高并发下绝不超发
日志异步落库：请求日志走消息队列异步消费，幂等保证不重复不丢失

5无状态实例 + 弹性伸缩

所有状态下沉到共享存储层，实例可随流量自由伸缩
无状态设计：实例本身不持久化任何业务数据，加减实例对业务完全透明
场景感知扩容：基于业务敏感的指标触发扩容，长连接流式场景下更灵敏
零停机升级：配合优雅关闭机制，滚动发布期间不丢流量不丢数据

6故障检测与熔断

主动探测 + 被动熔断 + 自动降级三重保障
三态熔断：渠道失败率超阈值自动熔断，冷却期后试探性放量，恢复正常再完整放行
主动探测：定时发送真实请求验证端到端可用性，不是简单的网络探活
降级链路：多级降级配置，主模型挂了切备选，备选挂了切兜底

7全链路可观测

结构化日志 + 指标监控 + 运营看板三位一体
请求追踪：每个请求有唯一 ID 串起全链路日志，每一跳都可追溯
决策可回溯：路由选择、熔断触发、敏感词命中等关键决策都有结构化日志
指标全覆盖：请求量、延迟、错误率、配额余额等核心指标实时采集
运营看板：多维度用量分析、模型运维指标、审计日志等运营工具齐备

★核心设计哲学 · 六大铁律

① 热路径零阻塞：所有同步 IO 下沉到异步队列，响应阶段永远不等数据库和消息队列
② 无状态实例：所有状态下沉到共享存储，单实例随时加减，滚动升级零停机
③ 分级缓存：本地微秒级 → 分布式毫秒级 → 数据库逐级回源，消息总线保证失效一致性
④ 故障快速恢复：熔断 + 健康检查 + 降级链，秒级摘除异常，渐进恢复避免雪崩
⑤ 观测优先：先有日志和指标再写功能，生产问题分钟级定位，而非小时级猜测
⑥ 一致性分级：配额强一致、日志最终一致，按业务特性选择

🔀场景化智能路由 · 迭代方向

当前决策完全依赖单一小模型（微调的Qwen3.5 4B），每个请求都做一次推理。迭代围绕"降成本、提准确、扩覆盖、保兜底"四个方向展开。

主要演进路径

  • 智能决策能力（规则优先 + 小模型兜底）简单请求用规则库快速判定，复杂或规则无法覆盖的请求再交给小模型，整体推理次数显著下降，延迟也随之降低。
  • 场景支持细分与独立配置从当前编程场景扩展到客服、写作、数据分析、内部办公等多场景，每个场景拥有独立的意图词表、模型映射和参数配置，互不影响。
  • 决策质量评估体系为每次路由决策建立可回放、可评估的机制，运营侧能清楚看到判对判错的分布、模型切换后的效果对比，持续优化决策策略。
  • 路由失败与高延迟兜底当决策过程本身失败（例如判别模型故障）或延迟超出阈值时，走预设的默认模型与默认路径兜底，保证请求不中断、用户无感知。

🧠Skill 知识注入 · 迭代方向

当前基于关键词匹配，用户换个问法就可能召回不到；命中后也缺少"是否真帮上忙"的反馈，Skill 库的优化主要靠人工维护。

主要演进路径

  • 语义召回升级从关键词匹配升级到语义匹配，用户同义表达、不同问法都能准确命中对应 Skill，显著提升覆盖率。
  • 效果闭环持续跟踪每条 Skill 注入后响应的质量信号（是否被采纳、是否追问类似问题等），低效 Skill 自动降权或下线。
  • Skill 协作与冲突仲裁多条 Skill 同时命中时进行合并、去重、优先级仲裁，避免内容互相打架导致输出质量下降。
  • 自进化（Self-Evolving）结合记忆工程能力，自动从用户高频使用的提问与解法中提炼候选 Skill，经效果验证后晋级为正式 Skill；已有 Skill 按使用数据自动精修、合并、淘汰，从"人工维护"走向"自我进化"（详见"记忆工程与 Skill 自进化"卡片）。

🛡️敏感词双向过滤 · 迭代方向

当前仅支持脱敏替换，对高危内容不能主动阻断；规则库扩大后扫描性能将成为瓶颈；不同业务对敏感度的要求也差异较大，需要分级管理。

主要演进路径

  • 严重度分级处置引入高危直接阻断、中危脱敏替换、低危仅记录不干预三档分级，关键请求可阻断并告警，不再只能事后发现。
  • 规则库治理为每条规则自动统计命中率、误报率，长期未命中或误报率高的规则给出淘汰建议，避免规则库越维护越臃肿。
  • 场景化规则集按业务域（金融、医疗、法务等）维护独立的规则库，不同团队启用不同规则集，兼顾合规严格性与业务灵活性。
  • 规则库持续更新机制建立与外部合规词库的订阅与同步机制，新增的敏感内容能及时纳入防护范围。

🎫令牌与配额管控 · 迭代方向

当前配额以 token 数为单位，业务方和财务看不到"实际花了多少钱"。费用维度的精细核算与管控是本能力最核心的演进方向，同时需要严格避免超扣、错扣。

主要演进路径

  • 费用维度的精准管控配额单位从"token 数"扩展到"金额"，按模型单价实时折算费用，业务方和财务直接看到"当月已花费 / 预算余额"。不同模型的价格差异、输入输出分别计价等复杂计费规则都可建模。
  • 超扣与错扣防护围绕计费的正确性建立多重校验，确保任何场景下都不出现"扣多了"、"扣重复了"、"扣错人"的问题。关键链路支持对账、追溯、回滚机制。
  • 预算管理体系支持按部门、项目、人员维度定预算，月度、季度、年度滚动核算，达到预算阈值自动告警。
  • 超支保护策略超预算后可配置多种处置方式：告警提醒、自动切换到便宜模型继续服务、直接阻断，满足不同业务的容忍度。
  • 用量预测与预算辅助基于历史趋势预测未来用量，辅助预算申报、提前发现异常消耗。

⚡多渠道高可用 · 迭代方向

当前能力已较为完善，覆盖负载均衡、健康检查、熔断降级、能力匹配等主要场景，短期内暂无专项迭代计划。后续如有新场景需求（如跨区域容灾等）再单独规划。

🔄跨协议转换 · 迭代方向

当前覆盖两种主流协议的常用字段，但 AI 生态迭代迅猛，新模型厂商和新协议特性的接入节奏需要持续跟进。

主要演进路径

  • 更多协议接入逐步扩展到 Gemini、通义、月之暗面等更多主流模型厂商的原生协议，让业务方接入新厂商不再受限于网关适配进度。
  • 字段完整性对齐对照各厂商官方能力清单定期核查字段覆盖度，避免新字段漏传影响客户端功能。
  • 厂商特性保留对各厂商特有的高级能力（如缓存标记、工具调用扩展、思考链控制等），在网关层能保留透传而不是被吞掉。
  • 协议版本演进适配厂商协议升级时能在网关侧平滑兼容老版本客户端，避免客户端被迫升级。

🔑BYOK 自带 Key · 迭代方向

BYOK 用户当前享受了安全过滤和审计，但用量数据未进入全局统计，公司看不到整体 AI 资源消耗。Key 的全生命周期管理也有进一步完善的空间。

主要演进路径

  • 用量透明化BYOK 请求的 token 消耗同样纳入日志与看板（不占用配额，但统计口径完整），公司拥有跨接入方式的全局 AI 用量视图。
  • Key 生命周期管理覆盖 Key 的录入、轮换、过期提醒、异常使用模式检测与告警、主动失效等完整生命周期。
  • BYOK 成本归因用户把厂商账单对齐到网关记录，确认"网关代理了哪些请求、产生了多少费用"，账实相符。
  • 同厂商多 Key 负载均衡团队可维护多把同厂商 Key 组成池，单 Key 被限流或失效时自动切换，提升 BYOK 场景的稳定性。

📊全链路可观测 · 迭代方向

当前指标覆盖了请求维度和渠道维度，但随着网关能力丰富，还需要补全更多细分指标，特别是围绕缓存、成本、用户体感的维度，支撑运营决策数据化。

主要演进路径

  • 缓存相关指标随着请求缓存能力上线，需要补全缓存命中率、缓存覆盖请求量、缓存降本效果（省下的 token 和金额）等核心指标，让缓存价值可量化。
  • 用户体感指标独立监控首字延迟、流式吐字速度等用户实际感知的指标，区分"整体耗时慢"和"首字慢"两种不同的体验问题。
  • 成本细分指标按模型、场景、部门、项目多维度拆解消耗与费用，支撑细粒度的成本分析和归因。
  • 变更观测新路由策略、新 Skill、新敏感词规则上线后自动对比上线前后的核心指标，数据驱动验证变更效果。
  • 流量回放脱敏后的生产流量可在预发环境回放，用来验证新策略不引入回归，降低上线风险。
  • 合规审计增强审计日志支持完整性证明和长周期归档，满足等保、金融等强监管行业的合规留痕要求。
  • 问题分钟级定位请求失败或变慢时，一键拉出该请求的完整决策链路（命中了哪些 Skill、路由到了哪个模型、哪一步耗时长）。

🏢渠道模式 · 迭代方向

当前已实现上游供应商隔离，覆盖核心的多租户隔离需求。短期内暂无专项迭代计划。后续如承载更多独立业务方时，会按需补齐租户级 SLA、租户级账单等运营层能力。

💾请求缓存 · 规划方向

相同或近似的请求没必要每次都打到大模型。网关层构建请求缓存体系，命中缓存时直接返回历史响应，兼顾降本和提速。

主要规划路径

  • 精准缓存完全相同的请求（相同的模型、相同的上下文、相同的参数）直接复用历史响应，适合固定问答、结构化分类等重复度高的场景。
  • 语义缓存含义相同但表达不同的请求（近似问法）通过语义匹配命中缓存，覆盖更多真实业务中"换种说法问相同问题"的情况。
  • 命中策略可控缓存启用粒度可按模型、场景、用户等维度精细配置，避免在需要最新响应的场景（如实时数据查询）误用缓存。
  • 缓存有效期管理针对不同内容类型设置合理的有效期，确保缓存内容的时效性与准确性。
  • 命中效果可观测配合可观测能力提供命中率、节省调用次数、节省费用等核心指标，让缓存的业务价值完全透明。

🧬记忆工程与 Skill 自进化 · 规划方向

网关天然是所有请求和响应的唯一穿透点，是做长期记忆最适合的位置。以"沉淀 → 反思 → 进化"三层架构，把用户使用过程中自然产生的信息转化为可复用的资产，让 Skill 库从人工维护迈向自我进化。

主要规划路径

  • 基础记忆沉淀在网关侧构建用户级长期记忆，自动提取并结构化存储个人偏好（代码风格、语言习惯、常用框架）、业务背景（所在部门、负责项目、常用术语）、历史行为（常问问题、反复遇到的坑），形成随调随用的个人画像。
  • 周期性反思与归因按日 / 周 / 月节奏对用户的会话进行摘要与归因：哪些任务重复出现、哪些套路反复奏效、哪些提问模式效果差。反思结果本身也进入记忆库，作为后续决策依据。
  • 候选 Skill 自动孵化从反思结果中自动识别出高频且高价值的片段（例如某人反复解释同一个业务术语、反复走同一个代码套路），生成候选 Skill，经效果验证后晋级为正式 Skill，完成"经验 → 可复用资产"的闭环。
  • 已有 Skill 数据驱动演进现有 Skill 库结合使用数据自动精修（命中率低的措辞调优）、合并（相似 Skill 去重）、淘汰（长期低效的自动下线），摆脱靠人工维护才能保持鲜活的困境。
  • 三层记忆分治公司级（统一规范与制度）、岗位级（角色通用经验）、个人级（独有偏好），分层存储、分层生效，匹配时按优先级叠加，既保护个性又复用共性。
  • 组织级泛化与知识流转个人记忆经脱敏后，可沉淀为同岗位、同部门的共性经验，一个人踩过的坑变成一个团队的默认知识，显著降低新人上手成本。
  • 隐私与合规底线记忆存储全程受用户控制——支持查看、导出、删除、暂停记忆；敏感内容（身份信息、密钥、代码机密）进入记忆前强制脱敏；BYOK 用户可独立选择是否启用记忆功能。
